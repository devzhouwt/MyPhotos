# 知识笔记生成

## 触发方式

用户显式调用 `/knowledge-note` 或明确表示"整理知识笔记""沉淀对话内容""生成学习笔记"。

## 输出位置

`docs/notes/YYYY-MM-DD-主题简述.md`

该目录为普通文档目录，不会触发 harness 自动加载。

## 笔记结构

每篇笔记包含以下三个板块：

### 一、概述

简要说明本次对话的背景、主题和核心收获（2-3句话即可）。

### 二、知识点清单

对对话中涉及的每个独立知识点，按以下格式逐一展开：

```markdown
### 知识点：{知识点名称}

**严谨定义**：
{用准确、无歧义的语言给出该概念/机制的定义}

**通俗理解**：
{用类比或日常语言解释，让非专业人士也能理解}

**触发关键**（仅 harness 相关知识点需要此小节）：
- 触发词：{列出触发该 skill/rule/agent 的关键词}
- 触发条件：{描述什么情况下会被激活}
- 所在路径：{文件或目录路径}

**易错点与补充**（从用户提问中提炼，仅当有相关发现时添加）：
- {提炼后的知识点，一句话讲清核心要点}
- {容易被忽略的边界情况或常见误解}
- {与其他概念的区分关键}
```

> **提炼原则**：不要罗列用户的原始提问和 AI 的回答原文。要分析提问背后暴露了什么知识盲区、什么误解、什么容易混淆的地方，然后将其精炼为一两条简洁的知识补充条目，挂到对应知识点末尾。多条提问如果指向同一类问题，合并为一条即可。

### 三、其他补充要点

仅收纳**无法归入上述任何一个知识点**的提炼内容。如果所有发现都已归入对应知识点的「易错点与补充」中，此板块可省略。

格式同上，以简洁的知识条目呈现，无需引用对话原文。

## 执行流程

1. **回扫对话**：回顾整个对话上下文，列出所有讨论过的知识点（去重、归类）。
2. **分析提问**：审视用户的每个提问，挖掘背后隐藏的知识盲区、误解和易混淆点。**不要记录问答原文**，要提炼为知识点。
3. **归类挂载**：将提炼出的易错点/补充点挂到对应的知识点下。无法归类的放入第三板块。
4. **生成笔记**：按上述结构组织 Markdown 内容。
5. **写入文件**：使用 Write 工具将笔记写入 `docs/notes/YYYY-MM-DD-主题简述.md`。
6. **告知用户**：报告笔记已生成及文件路径。

## 注意事项

- 每个知识点一个独立章节，避免混杂。
- 「易错点与补充」优先挂到对应知识点下，无法归类才放第三板块。
- **核心原则：提炼而非转录**——笔记是知识的结晶，不是对话的摘要。不出现"用户问……""AI 答……"这类对话记录。
- 提炼要精准，每条控制在 1-2 句话，直击要害。
- 对于 harness 相关知识点，务必标注触发关键。
- 笔记文件命名中的主题简述用中文，控制在 15 字以内。

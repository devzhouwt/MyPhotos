# 私人云相册 MVP PRD

## 问题陈述

作为用户，我希望拥有一个完全受自己控制的私人云相册，能够随时随地通过手机或电脑上传、浏览和管理我的照片与视频。现有的云相册服务（如 iCloud、Google Photos）需要将数据托管在第三方服务器上，而我希望照片数据存储在属于我自己的远程仓库中，同时保持前端代码简洁、可公开维护。

## 解决方案

构建一个纯前端单页面应用（SPA），托管在 GitHub Pages 上。照片和视频数据通过 Gitee OpenAPI 存储到用户自己的 Gitee 私有仓库中。代码与数据完全分离：前端代码在 GitHub 公开仓库，媒体数据在 Gitee 私有仓库。用户首次使用时配置自己的 Gitee 仓库地址和私人访问令牌（Personal Access Token），配置信息保存在浏览器 localStorage 中。无需后端服务器，零运维成本。

## 用户故事

1. 作为用户，我希望首次打开页面时能够设置自己的 Gitee 仓库地址和私人令牌，以便后续所有操作都能访问我的私有照片数据。
2. 作为用户，我希望创建新的相册，以便按主题或时间组织我的照片和视频。
3. 作为用户，我希望重命名或删除已有相册，以便灵活管理我的相册结构。
4. 作为用户，我希望通过拖拽或文件选择器批量上传照片和视频到指定相册，以便快速导入媒体文件。
5. 作为用户，我希望上传时能看到每个文件的进度条，以便了解上传状态。
6. 作为用户，我希望上传的照片能自动生成缩略图，以便在相册网格中快速浏览而无需加载原图。
7. 作为用户，我希望进入相册后以网格形式浏览所有照片缩略图，以便快速定位目标照片。
8. 作为用户，我希望点击照片后进入全屏灯箱预览，支持左右翻页和键盘导航，以便沉浸式浏览照片。
9. 作为用户，我希望在相册视图中可以切换到时间线模式，按上传时间分组浏览照片，以便回忆时间线。
10. 作为用户，我希望在灯箱预览中点击下载按钮下载单张照片的原图，以便保存到本地。
11. 作为用户，我希望在相册中多选照片后，以 ZIP 格式批量打包下载，以便一次性获取多张照片。
12. 作为用户，我希望能够在相册中多选照片后进行批量删除，以便清理不需要的媒体文件。
13. 作为用户，我希望将照片从一个相册移动到另一个相册，以便重新整理照片归属。
14. 作为用户，我希望为每个相册设置封面图，以便在相册列表中快速识别。
15. 作为用户，我希望从手机浏览器访问时页面能自适应手机屏幕，以便在移动端获得良好的浏览和上传体验。
16. 作为用户，我希望将页面添加到手机主屏幕（PWA），以便像原生 App 一样快速打开相册。
17. 作为用户，我希望已浏览过的照片能在离线时查看（PWA 缓存），以便在网络不佳时仍能访问。

## 实现决策

### 架构决策

- **代码数据分离**：前端代码托管在 GitHub 公开仓库并通过 GitHub Pages 部署；照片/视频数据通过 Gitee OpenAPI 存储在用户自己的 Gitee 私有仓库中。
- **纯前端 SPA**：无后端服务器，所有逻辑在浏览器中运行，Gitee API 调用直接从浏览器发起。
- **运行时配置**：Gitee 仓库地址和私人令牌由用户在前端设置页面填写，保存在浏览器 localStorage，每次 API 调用时从 localStorage 读取。
- **目录即相册**：Gitee 仓库中的目录结构直接映射为相册，目录名即相册名。每个相册目录下可存放 `.album-meta.json` 元数据文件（存储封面图、排序等相册级配置），该文件随相册数据一起存储在仓库中，换设备自动恢复。
- **GitHub Actions 自动部署**：Push 到 main 分支后自动构建并部署到 GitHub Pages。

### 技术栈

- 前端框架：React + Vite
- UI 组件库：shadcn/ui + Tailwind CSS
- 移动端：响应式 Web + PWA
- 构建部署：GitHub Actions → GitHub Pages
- HTTP 客户端：直接使用 Fetch API 调用 Gitee OpenAPI（注：上传场景因 Fetch 不支持上传进度跟踪，改用 XMLHttpRequest 获取 `upload.onprogress` 事件）

### 模块划分

**配置模块**

- 提供设置页面，用户输入 Gitee 仓库地址（owner/repo）、分支名称、私人访问令牌
- 配置保存到 localStorage，支持读取、更新、清除
- 首次访问时自动跳转到设置页面引导配置

**Gitee API 服务层**

- 封装 Gitee OpenAPI v5，统一注入 Token 鉴权
- 核心接口：获取目录树、获取文件内容/下载链接、创建文件（上传）、删除文件、创建目录
- 统一错误处理和重试逻辑
- API 端点前缀：`https://gitee.com/api/v5/repos/{owner}/{repo}`

**相册管理模块**

- 通过 Gitee API 获取仓库目录列表，每个目录即为一个相册
- 创建相册 = 在仓库中上传 `.gitkeep` 占位文件以创建目录（`.gitkeep` 仅作为技术手段维持目录存在，对用户完全不可见）
- 删除相册 = 递归删除目录下所有文件后删除目录
- 删除相册中最后一张照片时，同时删除 `.gitkeep`，目录自动消失（相册也随之消失）
- 重命名相册 = 遍历目录下所有文件，复制到新目录后删除旧目录
- 移动照片 = 复制文件到目标目录后删除源文件
- 封面图：每个相册可设置封面，封面图文件名存储在相册目录下的 `.album-meta.json` 元数据文件中（未设置时默认取目录中第一张照片作为封面）
- 批量操作说明：重命名相册、删除相册、移动照片均为逐文件串行操作，大相册可能耗时较长。采用分批策略：每批最多处理 200 个文件，批次间暂停 3 分钟以规避 Gitee API 频率限制，UI 显示当前批次进度（如 "正在处理第 1 批 45/200..."），全部批次完成后操作结束。批量操作期间整个应用进入全局锁定状态，禁止任何其他操作（包括页面切换），防止并发导致数据不一致（重新刷新页面或者通过其他设备访问该云相册时，也需要锁定，可以在仓库中增加系统文件，标识当前服务状态，避免在当前设备被锁定，但是相册操作没有全部完成时其他设备能操作的问题）。
- 移动照片：同时移动原图和对应的缩略图文件。移动过程若因网络中断等原因失败，执行完整回滚（源文件和缩略图均不删除），确保数据安全

**文件上传模块**

- 支持拖拽上传和点击选择文件上传，支持多文件同时上传
- 上传前使用 Canvas API 在客户端生成缩略图（宽度 300px），缩略图与原图以关联命名规则（如 `photo.jpg` 和 `photo.thumb.jpg`）一同上传
- 显示每个文件的上传进度（使用 XMLHttpRequest 的 `upload.onprogress` 事件获取实时上传字节数）
- 上传队列管理，支持同时上传多个文件
- 支持常见图片格式（JPG、PNG、GIF、WebP）和视频格式（MP4、MOV）
- 不支持的文件格式：前端校验文件扩展名和 MIME 类型，不支持的格式弹出 Toast 提示并拒绝上传
- 每个相册最多容纳 500 张照片（含视频），达到上限后禁止继续上传并提示用户
- MOV 格式说明：MOV 视频的浏览器播放支持取决于具体编码，推荐使用 MP4 以获得最佳兼容性
- 视频缩略图：MVP 阶段视频统一使用默认播放图标作为封面，不生成视频缩略图；网格视图中视频项显示文件名以便区分不同视频（后续迭代考虑客户端视频抽帧生成缩略图）

**媒体浏览模块**

- 文件列表过滤：获取目录文件列表后，过滤掉 `.gitkeep` 和 `*.thumb.*` 文件，两者均不展示在媒体网格中
- 网格视图：以固定尺寸网格展示缩略图，CSS `object-fit: cover` 统一裁剪
- 灯箱预览：点击照片全屏展示原图，支持左右箭头翻页、键盘左右键导航、ESC 关闭、双指缩放手势（移动端）
- 时间线视图：按时间分组排列照片，支持两种排序方式供用户切换：按 Gitee 仓库提交时间（默认）或按文件名排序
- 虚拟列表：大量照片时使用虚拟滚动，仅渲染可视区域的缩略图
- 图片懒加载：`loading="lazy"` 属性延迟加载屏幕外图片
- 视频支持：点击视频文件时内嵌播放器播放；网格视图中视频项使用默认播放图标占位，并叠加显示文件名以区分不同视频

**下载模块**

- 单张下载：直接使用 Gitee API 获取原始文件 URL 触发浏览器下载
- 批量下载：多选照片后，使用 JSZip 在浏览器中打包为 ZIP 文件后触发下载。批量下载总大小上限 200MB，超出后提示用户分批下载
- 下载前显示文件总大小估算，提醒用户大文件打包可能较慢

**PWA 模块**

- 配置 `manifest.json`：应用名称、图标、主题色、显示模式（standalone）
- 注册 Service Worker，采用以下缓存策略：
  - 静态资源（JS/CSS/字体）：Cache-First，首次安装后即缓存
  - 缩略图和原图：Stale-While-Revalidate，优先返回缓存内容（离线/弱网时秒开），后台静默发起网络请求更新缓存
  - 缓存上限约 200MB，超出后按 LRU 策略淘汰旧缓存
- 离线回退：无网络时仅能浏览已缓存的内容，上传、删除等写操作不可用

**CI/CD 模块**

- GitHub Actions 工作流：监听 main 分支 push 事件
- 仓库 Pages 设置：Source 设为 "GitHub Actions"（非 "Deploy from a branch"）
- 构建部署步骤：
  1. `actions/configure-pages` — 配置 Pages 构建参数
  2. `npm run build` — 构建前端产物
  3. `actions/upload-pages-artifact` — 将构建产物上传为 Actions Artifact
  4. `actions/deploy-pages` — 将 Artifact 部署到 GitHub Pages
- 全程使用 GitHub 官方 Actions，无需第三方部署 Action，无需维护 gh-pages 分支

### 路由设计

| 路由 | 页面 | 说明 |
|------|------|------|
| `/` | 相册列表页 | 展示所有相册，支持创建/删除/重命名/设置封面 |
| `/album/:name` | 相册详情页 | 网格/时间线视图，上传/多选/删除/下载 |
| `/settings` | 设置页面 | Gitee 仓库信息和 Token 配置 |

照片预览（灯箱）以浮层形式叠加在相册详情页上，无需独立路由。

### 空状态与错误处理

- **空相册列表**（无任何相册）：展示空白页面
- **空相册详情**（相册内无照片）：展示空白网格区域
- **API 调用失败**：在页面内嵌错误提示（非全局 Toast），包含错误原因和重试按钮
- **配置无效**：Token 无效或仓库地址错误时，重定向至设置页面并显示错误信息

### 数据流

```
用户操作 → React 组件 → API 服务层 → Gitee OpenAPI → Gitee 仓库
                                                        ↓
用户 ← React 组件 ← API 服务层 ← JSON 响应 ← Gitee OpenAPI
```

配置数据流：`用户输入 → localStorage → API 服务层读取注入请求头`

## 测试决策

- MVP 阶段暂不编写自动化测试，优先通过手动验收验证核心功能
- 后续若引入测试，应遵循「仅测试外部行为，不测试实现细节」原则
- 优先测试模块：Gitee API 服务层（接口契约）、配置模块（localStorage 读写）

## 范围外

- 用户登录/多用户系统（项目为单用户私人使用）
- 照片编辑/滤镜/裁剪功能
- AI 智能分类/人脸识别
- 照片分享/公开链接
- 评论/点赞等社交功能
- 视频转码/流媒体播放优化
- 原文 EXIF 信息提取与展示
- 照片标签/星标系统（预留后续迭代）
- 搜索功能（预留后续迭代）
- 相册级别的全量下载（预留后续迭代，文件太多时浏览器打包可能内存溢出）

## 补充说明

- Gitee OpenAPI 单文件上传大小限制约为 100MB，上传超过此限制的文件会失败，前端需在上传前校验文件大小（阈值 100MB）并提示用户。
- HEIC 格式不在支持列表中：HEIC 仅 Safari 浏览器原生支持，Edge/Firefox/OPPO 等主流浏览器均无法解码和生成缩略图，移除该格式以避免不可用的误导。
- Gitee API 有频率限制（未认证 5000 次/小时，已认证更高），单用户使用通常不会触及。
- GitHub Pages 仅支持 HTTPS，Gitee API 同样要求 HTTPS，不存在混合内容问题。
- 项目采用 MIT 开源协议，方便其他用户 Fork 后自行部署使用。
- 换设备使用时需在新设备上重新配置 Gitee Token，相册结构会自动从目录树恢复。
